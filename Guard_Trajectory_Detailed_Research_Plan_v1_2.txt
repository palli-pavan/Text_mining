3. Research objective and key questions

Aim: build a training-free, trajectory-aware safety controller for pretrained masked discrete diffusion language generation. It monitors intermediate states or predicted clean-text candidates, estimates safety risk, and decides whether to continue sampling or apply a validated intervention.

Question

Measurements

RQ1: Do intermediate states predict final violations before generation finishes?

AUROC/AUPRC, precision/recall, detection lead time, false alarms, risk trajectories.

RQ2: Does adaptive intervention reduce final violations compared with simple baselines?

Violation rate, absolute percentage-point reduction, paired confidence intervals.

RQ3: Does adaptive intervention improve the safety/quality/runtime trade-off?

Latency, overhead, PPL/reference quality, coherence, diversity, VRAM.

RQ4: Does scorer selection or an ensemble improve reliability?

Scorer accuracy, calibration, latency, disagreement, false positives and negatives.

4. Role of the reference paper

The uploaded reference, Constrained Discrete Diffusion (CDD), is a methodological and evaluation reference only. It evaluates constrained generation, including toxicity mitigation with RealToxicityPrompts and a toxicity surrogate trained on Jigsaw data. It also examines projection frequency/start-time and notes computational overhead. Therefore, our proposed contribution must not be presented as merely 'intervene late' or 'intervene less often'. The central hypothesis is that trajectory signals, risk persistence/uncertainty, and a risk-budgeted adaptive controller can inform when intervention is needed.

The first implementation gate is to inspect the real MDLM sampler and determine which intermediate states, logits, or predicted-clean distributions are accessible. Do not assume the API. Also, a scalar risk value added uniformly to every vocabulary logit cannot steer generation because it does not change softmax probabilities.

Use the pretrained `kuleshov-group/mdlm-owt` MDLM checkpoint from the official MDLM repository. We will not retrain the diffusion backbone. Start with short outputs and a small number of diffusion steps for debugging, then lock settings for experiments.

MDLM: pretrained, frozen; inference only.

Scorer candidates: use pretrained checkpoints first; benchmark on a held-out labeled set.

7. Proposed method and policies

Policy

Description

P0 baseline

Normal MDLM generation; no guard.

P1 post-hoc filter

Score final text; flag/reject without changing the generation trajectory.

P2 every-step

Score/intervene at every eligible step after a risk trigger.

P3 fixed interval

Score/intervene at a fixed interval.

P4 late start

Enable intervention after a predetermined part of reverse diffusion; ablation, not standalone novelty.

P5 adaptive trajectory

Use risk magnitude, persistence, scorer disagreement/uncertainty, diffusion stage and intervention budget.

P6 adaptive + ensemble

Adaptive policy with a validated scorer shortlist/ensemble.

P7 CDD comparison

Only if fair reproduction is feasible; report all deviations.

Before a real intervention is implemented, test monitor-only mode. If a black-box scorer returns only one scalar, do not pretend that scalar is a valid gradient for token-level steering. The intervention must explicitly change token-specific preferences or perform a justified constrained projection/reranking operation, and must pass tests for normalization, NaNs, and guard-off equivalence.

9. Metrics

Metric

Definition / purpose

Violation rate

100 × outputs with final score > threshold / all evaluated outputs.

Absolute reduction

Baseline violation rate minus method violation rate in percentage points.

Early-detection recall

Share of eventual violations flagged at least a specified number of steps before completion.

AUROC/AUPRC

Predict final violation from intermediate risk; use AUPRC especially for imbalanced labels.

Precision/false-positive rate

Quantifies false alarms/overblocking.

Quality

Fixed reference-model PPL or score, coherence/relevance rubric, diversity metrics.

Runtime

Wall-clock time per sample and overhead: (method time − baseline time)/baseline time × 100%.

Resource use

Peak GPU VRAM and, where feasible, CPU RAM.

Intervention rate

Actual interventions / eligible decision points, plus count per sample.

16. Complete recommendation checklist (consolidated)

This section consolidates the project recommendations so the plan can be followed as an implementation checklist. Items are recommendations, not claims that the experiments have already been completed.

16.1 Research scope and claims

Keep the pretrained MDLM generator fixed and frozen. The primary comparison is between safety scorers and monitoring/intervention policies, not between 20–30 separately trained diffusion generators.

Treat Constrained Discrete Diffusion (CDD) as a reference and possible external baseline, not as the proposed method to copy. A CDD comparison is optional until a fair, reproducible implementation is feasible.

Do not claim novelty based only on late intervention or lower intervention frequency; the reference paper already studies projection frequency and start time.

Frame the core hypothesis around trajectory-aware early warning, risk persistence, uncertainty/disagreement, diffusion stage, and an explicit intervention budget. Claim these as contributions only if evidence supports them.

Perform a focused literature review before making novelty claims, and compare methods under matched prompts, seeds, scoring thresholds, and compute settings where possible.

Report negative, mixed, or null results honestly. Do not invent numbers, plots, significance, or successful model runs.

16.2 Data and prompt design

Use RealToxicityPrompts as the primary end-to-end generation benchmark. Record dataset version, source IDs, exact filtering criteria, and exclusions.

Use Jigsaw Toxic Comment Classification Challenge as labeled data for scorer validation and, only if necessary, training one small auxiliary classifier. Keep train, validation, and test data separate.

Consider Civil Comments, ToxiGen, and ETHOS only as secondary robustness checks after the main pipeline works; document label differences and avoid treating hate, offensiveness, and toxicity as identical labels.

Create a reproducible prompt manifest with prompt ID, split, seed, prompt text or source reference, model/checkpoint revision, policy/config version, and run status.

Use prompt-level development/validation/test splits to prevent prompts or near-duplicates from leaking across splits. Tune thresholds and policies on development/validation only.

For controlled stress tests, add clearly labeled safe, ambiguous/boundary, and unsafe prompt categories. Cover relevant broad categories such as harassment, hate, self-harm, violence, dangerous instructions, sexual content, illegal activity, and privacy. Keep unsafe examples non-operational and use them only for evaluation; document how they were constructed.

Pair prompts and random seeds across all policies. Begin with 5 prompts × 1 seed for debugging, 25–50 prompts for the pilot, and target 200–500 prompts × 3 seeds for the main study if compute permits. Treat 1,000 samples as a stretch goal, not a requirement.

Do not download or retrain on OpenWebText for the initial project; it is the provenance of the pretrained MDLM checkpoint, not the primary safety evaluation dataset.

16.3 Model and scorer registry

Build a registry of 20–30+ candidate safety scorers across dedicated toxicity classifiers, hate/offensive-language classifiers, lightweight alternatives, model/checkpoint variants, and optional moderation APIs. NLI/semantic-risk models should only be included for a clearly defined auxiliary task.

Verify exact checkpoint IDs, revision hashes, licenses, label names/order, score semantics, tokenizer requirements, model size, and hardware compatibility before counting a candidate as tested.

Store attempted, loaded, compatible, benchmarked, and failed statuses separately. Report the actual number of models evaluated; do not present a list of model names as completed experiments.

Smoke-test each candidate first, then benchmark compatible candidates on cached text so scorer comparisons use the same examples. Load models sequentially where memory is limited.

Evaluate scorers using AUROC, AUPRC, precision, recall, F1, confusion matrices, false-positive/false-negative analysis, calibration (Brier score/ECE if feasible), inference latency, and memory use.

Compare the strongest validated single scorer with simple mean/max combinations and a disagreement-aware ensemble. Fit any calibration or ensemble weights using validation data only.

Use an independent final evaluator where feasible to reduce circular evaluation. State clearly that proxy toxicity classifiers can be biased, imperfect, and sensitive to dialect or topic.

16.4 Implementation order and technical safeguards

First verify the actual Conda/Python/PyTorch/CUDA setup and run a short, unguarded MDLM baseline from the official repository. Save the full command, environment versions, logs, configuration, and generated output.

Inspect the actual MDLM reverse-sampling loop before writing adapters. Identify what is available at each step: masked state, logits, predicted clean tokens/text, confidence, entropy, mask count, timestep, and any supported callback. Do not assume these values or APIs exist.

Implement monitor-only trajectory logging before any intervention. With fixed prompts and seeds, prove that enabling the logger does not change the generated output or baseline behavior.

Log at least timestep, current state/reference, predicted-clean candidate where available, risk score, entropy/confidence if available, masked-token count/fraction if available, policy decision, actual intervention applied, intervention reason, and per-step runtime. Avoid logging sensitive data unnecessarily.

Distinguish a proposed intervention from an intervention actually applied. Update last-intervention timestamps/counters only after a real change is applied.

Never add a scalar risk score uniformly to every vocabulary logit: this does not change the softmax distribution. A valid intervention must make token-specific changes or use a justified projection, constrained mask, candidate reranking, or resampling method supported by the sampler.

Add unit tests for policy decisions, intervention behavior, probability normalization, no NaNs/Infs, deterministic behavior under fixed seeds, and guard-off/no-op equivalence. Test on tiny examples before running full experiments.

Preserve the pretrained MDLM weights. Start with batch size 1, short sequences (64–128 tokens), and 25–50 steps; use sequential scorer loading and CPU fallback for models that do not fit in 4 GB VRAM. Increase scale only after profiling.

Keep a clear separation between proposed policy decision, attempted intervention, successful intervention, and final outcome. Record exceptions, timeouts, OOM errors, and failed runs rather than silently dropping them.

16.5 Policies and experiments to compare

P0: unguarded baseline MDLM.

P1: post-hoc final-output filter/flag; report rejection or regeneration costs and do not portray it as in-trajectory steering.

P2: intervention at every eligible step after a defined trigger.

P3: fixed-interval intervention.

P4: fixed late-start intervention as an ablation/control, not the sole novelty claim.

P5: adaptive trajectory policy using risk magnitude, persistence/trend, uncertainty or scorer disagreement, diffusion stage, and intervention budget.

P6: adaptive policy with a validated scorer ensemble.

P7: CDD-inspired/external comparison only if implementation, compute, thresholds, and evaluation are sufficiently comparable; clearly report deviations.

Run baseline and monitor-only experiments first, then trajectory-prediction tests, policy comparisons, scorer benchmark, ensemble comparison, threshold sensitivity, ablations, robustness tests, and optional external comparison.

Ablate trajectory information, timestep/stage, uncertainty/disagreement, risk trend/persistence, thresholds, checking intervals, intervention budget, scorer count, and ensemble method. Include an intervention-off control.

16.6 Metrics and statistical reporting

Report violation rate with the exact scorer and threshold; absolute percentage-point reduction; relative reduction where useful; and paired confidence intervals.

Report early-warning AUROC/AUPRC, precision, recall, false-alarm rate, lead time before generation ends, and intervention success rate.

Report output quality using a fixed reference-language-model perplexity where meaningful, coherence/relevance evaluation with a stated rubric or judge, and diversity measures such as distinct n-grams, entropy, or self-BLEU with exact protocol.

Report latency per sample, runtime overhead = (method time − baseline time) / baseline time × 100%, number of extra scorer calls/forward passes, intervention count/rate, peak GPU VRAM, and CPU RAM where feasible.

Use bootstrap 95% confidence intervals over prompts and paired prompt/seed comparisons. Report sample counts and missing/failed runs. Account for multiple comparisons when evaluating many scorers, and distinguish exploratory analysis from confirmatory tests.

Choose thresholds on validation data, then freeze them for test evaluation. Report scorer-specific thresholds rather than assuming one numeric threshold is comparable across models.

Include error analysis: representative successful and failed trajectories, false positives, false negatives, overblocking, quality degradation, and cases where scorers disagree.

16.7 Complete visual-analysis catalogue

Generate every result figure from actual raw CSV/JSONL logs with scripts. Include units, sample sizes, confidence intervals where appropriate, readable legends, fixed definitions, and reproducible filenames. The following catalogue supplements the tables already present in Section 2.

Risk trajectory line plots with confidence bands, separating outputs that eventually pass/fail the final safety threshold.

Entropy and token-confidence trajectories over reverse steps, where these quantities are accessible from the real sampler.

Masked-token count/fraction over steps, and risk-versus-mask-fraction plots, where the sampler exposes masks.

Risk score versus timestep and risk score versus intervention strength/gamma, only if an intervention-strength parameter is implemented and logged.

Token-level heatmaps showing which positions/tokens were masked, predicted, flagged, or changed by an intervention; use only where the method can support accurate token attribution.

ROC and precision–recall curves for early prediction of final violations, including lead-time analyses.

Bar or dot-and-whisker plots of violation rates with 95% confidence intervals and sample counts.

Safety–quality and safety–runtime Pareto plots; runtime overhead versus violation rate; quality loss versus violation reduction.

Box/violin plots of toxicity score, PPL, coherence score, latency, memory, scorer calls, and actual intervention counts.

Scorer comparison horizontal bars for AUROC/AUPRC/F1/calibration/latency, plus confusion matrices for selected scorers.

Scorer correlation/disagreement heatmaps and heatmaps of false-positive/false-negative patterns across categories.

Calibration/reliability curves, plus Brier score or ECE summaries if probability calibration is appropriate.

Final toxicity-score histograms/density plots per policy with the chosen threshold marked.

Individual trajectory plots for representative true-positive, false-positive, false-negative, and successful-intervention cases.

Ablation plots for threshold, persistence, check interval, intervention budget, ensemble size, uncertainty use, timestep use, and risk trend.

Failure-case gallery/table and category-wise results for safe, ambiguous/boundary, and unsafe prompt groups.

Plots must be reproducible from scripts and raw logs. Clearly label any design illustration as illustrative; never mix illustrative values with experimental results.

16.8 Paper, ethics, and reproducibility package

Prepare the conference paper with title, abstract, keywords, introduction, problem definition, related work, method, system/algorithm, datasets, experimental setup, baselines, metrics, results, statistical analysis, ablations, limitations, ethics, conclusion, and references.

Include a method diagram, sampler/controller pseudocode, dataset statistics table, model registry table, main comparison table, ablation table, runtime/resource table, and all figures that answer the research questions.

Include a supplementary appendix with detailed configurations, hyperparameters, threshold selection, model IDs/revisions/licenses, prompt filters, seed policy, additional plots, failure cases, and reproducibility instructions.

Publish or archive code/configs, manifests, environment specification, exact commands, scripts for processing logs and regenerating plots, and an explanation of any unavailable model/API or failed run.

Document dataset/model licenses and intended use. Minimize exposure of personal data; keep unsafe prompt examples non-operational; discuss proxy-classifier bias, overblocking, underblocking, generalization limits, and computational limitations.

Use the correct conference template and citation style after selecting a target venue. Do not claim a submission-ready paper until results, references, and reproducibility artifacts have been checked.
